# 3. Root Cause Analysis

## Investigation Performed

The `renderActionButtons()` function in `OrderTable.jsx` was inspected.

Buttons were rendered using:

```js
data-action=""
```

and:

```js
<span class="action-icon">
```

while click handling logic depended on:

```js
const action = $(this).data('action');
```

and:

```js
if (action === 'payment') ...
if (action === 'processed') ...
if (action === 'dispatched') ...
```

## Root Cause Identified

The arrow and eye icons were missing valid `data-action` attributes.

Because of this:

* Click events fired
* But no matching action condition executed

---

# 4. Fix Applied

## File Modified

* `OrderTable.jsx`

## Changes Performed

### Arrow Button Fix

Changed:

```js
data-action=""
```

To:

```js
data-action="processed"
```

This connected the arrow icon to:

```js
hanelProcessed(data.orderId)
```

which opened the `Processed` modal.

---

### Eye Button Fix

The eye icon had no action assigned.

A minimal debugging-safe solution was applied by mapping:

```js
data-action="payment"
```

This reused the already-working payment modal logic.

# 2. Database Architecture Decision

## Final Architecture Chosen

One MySQL Server → Multiple Databases

```text
MySQL Server
│
├── drone_forensics
│     └── Military UAV reference database
│
└── uav_marketplace
      └── UAV marketplace/catalog database
```

## Reasoning

The military database and marketplace database were intentionally isolated because:

| Military DB                   | Marketplace DB            |
| ----------------------------- | ------------------------- |
| Reference system              | Commercial catalog        |
| Country/platform intelligence | Products/components       |
| Historical/reference data     | Seller/pricing data       |
| No pricing                    | Marketplace-focused       |
| Read-heavy                    | Transaction/catalog-heavy |

This separation:

* Prevents schema pollution
* Maintains normalization
* Keeps future extensibility clean
* Allows independent scaling
* Preserves forensic integrity

# 8. Important Engineering Lessons Learned

## A) Catalog Data ≠ Numeric Data

Initial ingestion failed because:

* CSV values contained:

  * ranges
  * units
  * empty strings
  * text annotations

Examples:

```text
3-6S
35A
500W+
N/A
```

### Final Decision

All catalog ingestion fields stored as:

```sql
VARCHAR
```

Normalization/parsing deferred to future derived logic.

---

## B) Excel CSV Corruption Issue

Excel automatically converted values like:

```text
6-4
```

into:

```text
6-Apr
```

This caused ingestion anomalies.

### Final Best Practice

* Never preprocess CSVs in Excel
* Use:

  * VS Code
  * Notepad++
  * raw CSV editing

---

## C) Stored Procedure Engineering

### Issues Encountered

* Procedures not executing in MySQL Workbench
* Duplicate inserts
* Primary key collisions

### Solutions Applied

* Use `INSERT IGNORE`
* Add uniqueness constraints
* Use `NOT EXISTS`
* Recreate procedures after schema changes

# Drone Forensics Backend Project — Complete Development Summary

## 1. Project Overview

The project focused on designing and implementing a **production-ready MySQL backend database** for a **Military Drone / UAV Forensics System**.
The objective was to build a scalable backend capable of:

* Storing drone platform and variant data from multiple countries
* Supporting future frontend integration
* Handling real-world CSV datasets with inconsistent formatting
* Enabling fast filtering, searching, and querying
* Supporting future modules such as:

  * UAV Marketplace
  * Drone Parts Forensics
  * AI / Embedding Search
  * Case Management

The backend was developed using:

* **MySQL 8.0**
* **MySQL Workbench**
* **CSV-based ETL pipeline**
* **Normalized relational schema design**

---

# 2. Database Architecture and Design

## 2.1 Database Creation

A dedicated database was created:

```sql
CREATE DATABASE IF NOT EXISTS drone_forensics
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;
```

### Why this was used:

* `utf8mb4` supports international text and Unicode
* Future-proof for multilingual datasets
* Compatible with APIs and frontend frameworks

# 8. Major Errors Encountered and Fixes Applied

## 8.1 Error: `secure_file_priv`

### Problem

MySQL blocked CSV import:

```text
Error Code: 1290
The MySQL server is running with the --secure-file-priv option
```

### Cause

MySQL only allows imports from a secure directory.

### Solution

Used:

```sql
SHOW VARIABLES LIKE 'secure_file_priv';
```

Moved CSVs to:

```text
C:\ProgramData\MySQL\MySQL Server 8.0\Uploads\
```

Corrected path format:

```sql
'C:/ProgramData/MySQL/MySQL Server 8.0/Uploads/file.csv'
```

---

## 8.2 Error: Incorrect Decimal Value (`N/A`)

### Problem

CSV contained:

```text
N/A
```

for numeric columns.

### Error Example

```text
Incorrect decimal value: 'N/A'
```

### Solution

Used:

* `@variables`
* `NULLIF()`

Example:

```sql
@OperationalRange_km
```

Then:

```sql
OperationalRange_km = NULLIF(@OperationalRange_km, 'N/A')
```

---

## 8.3 Error: Incorrect Integer Value (`IntroductionYear`)

### Problem

`IntroductionYear` contained `N/A`.

### Fix

Converted:

```sql
IntroductionYear
```

to:

```sql
@IntroductionYear
```

Then:

```sql
IntroductionYear = NULLIF(@IntroductionYear, 'N/A')
```

---

## 8.4 Error: Encoding / Character Set Issues

### Problem

Brazil dataset caused errors:

```text
Incorrect string value '\xF3'
```

### Cause

Latin-1 encoded CSVs.

### Solution

Used:

```sql
CHARACTER SET latin1
```

during `LOAD DATA INFILE`.

UTF-8 remained the table storage encoding.

---

## 8.5 Error: Semantic Text in Numeric Fields

### Problem

USA dataset contained:

```text
Unlimited SATCOM
```

inside numeric columns.

### Error

```text
Incorrect decimal value
```

### Final Professional Solution

Used:

```sql
CASE + REGEXP
```

Example:

```sql
CASE
WHEN @DataLinkRange_km REGEXP '^[0-9]+(\\.[0-9]+)?$'
THEN @DataLinkRange_km
ELSE NULL
END
```

This became the final robust ingestion strategy.

---

## 8.6 Duplicate Index Errors

### Problem

```text
Duplicate key name
```

### Cause

Indexes already existed.

### Resolution

Confirmed using:

```sql
SHOW INDEX FROM drone_variants;
```

No further action required.
