# UAV Marketplace Backend System — Project Summary

## 1. Project Objective

The objective of the project was to design and develop a scalable backend system for a UAV (drone) marketplace and compatibility engine using:

* MySQL
* Node.js
* CSV-based ingestion pipelines
* Stored Procedures
* Relational database architecture

The system was intended to:

* store drone component datasets,
* support advanced filtering,
* validate compatibility between parts,
* generate complete drone builds,
* and power a frontend marketplace application.

The backend architecture was designed similarly to systems like PCPartPicker, but specifically for UAV components.

# 8. CSV Loading Strategy

## Initial Problem

Using direct column mapping:

```sql
LOAD DATA INFILE ...
(
 column1,
 column2
)
```

caused silent failures.

Symptoms:

* “350 rows returned”
* but staging table count = 0

---

## Root Cause

Column mismatches between:

* CSV structure
* and table structure

caused rows to be skipped silently.

---

## Final Solution

A safer variable mapping strategy was implemented:

```sql
(@c1,@c2,@c3...)
SET
 column1 = TRIM(@c1),
 column2 = TRIM(@c2)
```

Advantages:

* safer ingestion,
* handles column inconsistencies,
* easier debugging,
* production-ready approach.

---

# 9. Character Encoding Errors Faced

## Error Encountered

```text
Error Code: 1300
Invalid utf8mb4 character string
```

---

## Cause

CSV encoding mismatch during:

```sql
LOAD DATA INFILE
```

---

## Solution

Added:

```sql
CHARACTER SET latin1
```

inside `LOAD DATA INFILE`.

---

# 10. Line Termination Issues

## Problem

CSV rows were not loading correctly.

---

## Cause

Mismatch in:

* `\n`
* vs `\r\n`

line endings.

---

## Solution

Adjusted:

```sql
LINES TERMINATED BY '\n'
```

or

```sql
LINES TERMINATED BY '\r\n'
```

depending on file format.

---

# 11. Manufacturer Mapping Issue

## Problem

Stored procedures inserted zero rows even though staging tables had data.

---

## Cause

JOIN mismatch:

```sql
m.name = s.Brand
```

failed due to:

* extra spaces,
* case differences,
* inconsistent manufacturer names.

---

## Solution

Normalized all manufacturer comparisons using:

```sql
UPPER(TRIM(...))
```

Example:

```sql
ON m.name = UPPER(TRIM(s.Brand))
```

This fixed all JOIN failures.

# 4. Major Initial Data Issue

## Problem

Incorrect values were inserted into ML dataset:

* `motor_id` was being treated as `motor_kv`
* IDs were mistakenly used as specifications

Example issue:

```text
motor_kv = 100
```

but 100 was actually `motor_id`.

## Root Cause

Wrong column mapping during INSERT query.

## Fix

Rebuilt dataset using proper joins:

```sql
m.kv_rating
e.continuous_current_a
p.diameter_in
b.cell_count
```

instead of IDs.

# 5. Negative Dataset Creation

## Initial Problem

Negative data was unrealistic/random:

* constant values
* invalid physics
* missing battery values
* no real incompatibility patterns

Result:

## Fix

Created rule-based negative samples:

* oversized propellers

* unsafe battery cell count

Used SQL-based generation from valid builds.

Example logic:

```sql
prop_diameter > frame_size
motor_kv > 3000
```

## Problem

## Root Cause Found

* `drone-dashboard.css`

which overrode new dark theme.

## Fix Applied

```css
background: linear-gradient(...) !important;

```

Also added:

```css
.component-card * {

}
```

to override nested purple/dark text.
